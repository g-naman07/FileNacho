# FileNacho

FileNacho is a browser based peer-to-peer file transfer app. Choose a file, share a link with the recipient, and send the file directly between browsers using WebRTC. A small Node.js WebSocket service coordinates the connection; it does not store or relay file contents.

## Features

- Share a file through a room link generated by the sender.
- Transfer data browser to browser with a WebRTC data channel.
- Split files into chunks and apply backpressure while sending.
- Compress eligible files in the browser with Huffman coding; common already-compressed formats skip this step.
- Download the received file from the recipient's browser.

## Requirements

- Node.js and npm
- Two browsers/devices to try a transfer

## Get started

Run the signaling server and frontend in separate terminals from the repository root.

### 1. Start the signaling server

```bash
cd backend
npm install
npm run dev
```

The server listens on `http://localhost:5000` by default and accepts the WebSocket signaling connection used by the frontend. Set `PORT` to change the port. Set `FRONTEND_URLS` to a comma-separated list of allowed frontend origins if the frontend is served from a different origin; the default is `http://localhost:5173`.

### 2. Start the frontend

In another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the Vite URL shown in the terminal (normally `http://localhost:5173`). The app connects to `ws://localhost:5000` by default. To use a different signaling server, create `frontend/.env` with:

```env
VITE_SIGNALING_SERVER_URL=wss://your-signaling-server.example
```

Restart Vite after changing environment variables. Use `wss://` when the deployed frontend is served over HTTPS.

### 3. Send a file

1. Select a file on the sender page and choose **Get Shareable Link**.
2. Send the generated `/receive/...` link to the recipient.
3. Keep the sender page open while the recipient opens the link and the transfer completes.
4. The recipient can download the file when it is ready.

The sender's selected file is held in the current browser page, so do not refresh or close that page before the transfer finishes. The signaling server matches peers by room while their connections are active.

## Project layout

```text
backend/   Node.js HTTP and WebSocket signaling server
frontend/  React and Vite application, WebRTC transfer, compression and chunking
```

## Development commands

From `frontend/`:

```bash
npm run build   # Create a production build in frontend/dist
npm run preview # Preview the production build locally
npm run lint    # Run ESLint
```

From `backend/`, run `npm start` to start the signaling server without the nodemon development watcher.
